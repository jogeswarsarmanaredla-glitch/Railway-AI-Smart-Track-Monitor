# Railway AI – Smart Track Monitoring

An independent industrial health monitoring system for railway tracks, integrating multi-axis vibration telemetry ($V_x, V_y, V_z$), environmental metrics (temperature and humidity), Machine Learning-based track fault detection & anomaly scoring, and persistent storage in PostgreSQL 18.6 with SQLAlchemy 2.0.

---

## ⚠️ Important Data Source & Benchmark Notice
> **NOTICE:** All sensor readings, vibration traces, and diagnostic alerts currently provided or simulated by this system are **strictly synthetic mock data** generated by the simulation engine (`SYNTHETIC_SIMULATION_ENGINE`). No external unverified live railway data is represented as genuine.
> 
> **Non-Operational Safety Disclaimer:** The machine learning models were trained and evaluated exclusively on synthetic benchmark telemetry. Model predictions and maintenance suggestions represent algorithmic diagnostic signals and do not certify actual operational railway safety.

---

## 🛠️ Technology Stack

- **Frontend:** React 18, Vite, TypeScript, Tailwind CSS, Lucide React, Recharts
- **Backend:** Python 3.14, FastAPI, Pydantic v2, CORS middleware, In-memory ring buffer telemetry simulator
- **Database:** PostgreSQL 18.6, SQLAlchemy 2.0 (Declarative), Psycopg 3
  - **Tables:** `track_segments`, `sensor_telemetry`, `ml_predictions`, `alerts`
  - **Architecture:** Hybrid persistence (asynchronous batch writes + startup circular buffer hydration)
- **Machine Learning Engine:** Scikit-learn, NumPy, Pandas, SciPy, Joblib
  - **Fault Classifier:** `RandomForestClassifier` (100 estimators, balanced class weights)
  - **Anomaly Detector:** `IsolationForest` (trained strictly on nominal synthetic baseline, calibrated threshold: `0.75`)
  - **Feature Extractor:** 23-dimensional rolling window statistical & physical features ($W=20$ samples)
- **Design System:** Responsive Industrial Dark Theme (`#070a11` / `#0b0f19`)

## 🗄️ PostgreSQL Database Schema (Phase 4)

| Table Name | Description | Key Constraints & Indexes |
|---|---|---|
| `track_segments` | Railway track infrastructure lines (`TRK-01` to `TRK-04`) | Primary Key: `id`, Unique: `code`, Index: `health_status` |
| `sensor_telemetry` | Time-series readings ($V_x, V_y, V_z$, temp, hum, speed) | Primary Key: `id`, Unique: `reading_id`, Composite Index: `(track_segment_id, timestamp)` |
| `ml_predictions` | AI fault diagnoses, anomaly indices, feature snapshots | Primary Key: `id`, Unique: `prediction_id`, Composite Index: `(track_segment_id, timestamp)` |
| `alerts` | Incident notifications, severity levels, acknowledgment state | Primary Key: `id`, Composite Index: `(acknowledged, severity, timestamp)` |

## 🚀 Exact Startup Instructions

### 1. Backend (FastAPI + PostgreSQL)

1. Open a terminal in the project root:
   ```powershell
   cd backend
   ```
2. Start the FastAPI development server:
   ```powershell
   ..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
   ```
3. Endpoints:
   - **Interactive API Documentation (Swagger):** [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
   - **Health Check Endpoint:** [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health)
   - **Dashboard Summary:** [http://127.0.0.1:8000/api/v1/dashboard/summary](http://127.0.0.1:8000/api/v1/dashboard/summary)
   - **ML Model Metadata & Holdout Metrics:** [http://127.0.0.1:8000/api/v1/ml/model-info](http://127.0.0.1:8000/api/v1/ml/model-info)

---

### 2. Frontend (React + Vite + TypeScript)

1. Open a second terminal in the project root:
   ```powershell
   cd frontend
   ```
2. Launch the Vite development server:
   ```powershell
   npm run dev
   ```
3. Open your browser:
   - **Frontend UI Console:** [http://127.0.0.1:5173](http://127.0.0.1:5173)
